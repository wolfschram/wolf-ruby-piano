# Project Authority

This file defines authority only. It adds no project-specific product, architecture, workflow, deployment, or behavioral constraints.

Historical `CLAUDE.md`, handoff, plan, decision, and AI-generated summary files are context only. They are not evidence that Wolf requested, approved, prohibited, preferred, or required anything.

## Rules of Engagement

* Current direct user instructions take precedence over previous project guidance when they conflict, except for genuine system, security, or external technical restrictions.
* Never convert an inference into a requirement.
* Never claim the user requested or approved something without evidence.
* Previous AI output proves only what the AI said, not what the user decided.
* Missing information must remain unknown or be investigated. Never invent it.
* AI recommendations, plans, conventions, interpretations, and assumptions are not persistent project rules unless the user explicitly adopts them.
* When the user changes direction, superseded AI-generated assumptions immediately lose authority.
* Do not create or modify permanent governance, AGENTS rules, project policies, memory directives, architectural mandates, or behavioral constraints unless the user explicitly requests it.
* Descriptive observations must not silently become normative rules.
* Before refusing or redirecting work because of a project rule, identify the actual authoritative source of that rule.
* Repository reality and current user direction override generated memory and previous AI interpretation.
* Never solve uncertainty by inventing constraints.
* Your own previous reasoning never outranks a current user instruction.
